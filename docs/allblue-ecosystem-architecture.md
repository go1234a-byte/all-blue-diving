# 올블루 생태계 아키텍처 (현재 구현 기준)

## 두 제품의 역할
- **투어 앱 (All Blue Tour)**: 투어 탐색, 예약, 결제, 강사·센터, 투어 일정, 취소·환불. 백엔드는 Supabase(Postgres + Auth + Edge Functions).
- **다이브 컴퓨터 (컴패니언 + Apple Watch 앱)**: 실제 다이빙 수행과 기록. 감압 계산은 `Sources/DiveCore`에만 있다. 로컬 우선(Offline First).

원칙: 같은 기능을 두 번 만들지 않는다. 투어 앱은 계획을 관리하고, 다이브 컴퓨터는 실제 다이빙을 기록한다. 둘은 **여행(Trip)** 으로 연결된다.

## 연결 구조

```
투어 앱 (Supabase)                         다이브 컴퓨터
───────────────────────                    ─────────────────────────
tours ─┬─ bookings (Trip 역할)             워치: 실제 다이빙 → 로컬 기록
       ├─ tour_dive_plans (강사 계획)          │ WatchConnectivity
       └─ tour_change_log (변경 이력)          ▼
                                            아이폰: DiveLogEntry (로컬 JSON)
                ▲   로그인 (AccountStore)         │
                └─────────── 업로드 ──────────────┘
                              dive_logs (실제 기록, 원본 불변)
                              devices   (기기 등록)
```

## 원본(Source of Truth)
| 데이터 | 원본 | 저장 위치 |
|---|---|---|
| 투어, 예약, 결제, 강사, 센터 | 투어 앱 | Supabase `tours`, `bookings`, ... |
| 강사 계획 (예정 다이빙) | 강사 | Supabase `tour_dive_plans` (참고용) |
| 투어 변경 이력 | 트리거 자동 기록 | Supabase `tour_change_log` |
| 실제 다이빙 기록 | 다이브 컴퓨터 | 워치/아이폰 로컬 → Supabase `dive_logs` |
| 기기 등록 | 컴패니언 | Supabase `devices` |

절대 원칙: 투어 앱은 실제 다이빙 데이터를 만들거나 고치지 않는다. 업로드된 `dive_logs.payload`는 수정하지 않는다.

## 현재 구현된 것 (P0 + P1)
- 로그인: 컴패니언 설정 → 계정 (기존 `AccountStore`, 이메일 인증 코드)
- 내 여행: 확정된 예약 목록, 취소 표시, 강사 계획, 변경 이력
- 기록 업로드: 중복 방지, 날짜 기준 여행 자동 연결 / 직접 선택 / 연결 안 함, 실패분 재시도
- 올린 기록: 실제값과 계획값 비교 (같은 여행, 같은 날짜)
- 강사: 투어 편집 화면의 "예정 다이빙 계획" 편집기

## 아직 없는 것
- 게스트 예약(로그인 없이 한 예약)과 계정 연결
- 워치가 직접 클라우드에 올리는 것 (지금은 아이폰이 대신 올림)
- 여러 기기 등록 화면, 캘린더 연동, 비상 연락처
- 같은 날 다이브가 여러 번일 때의 정확한 계획 매칭 (지금은 첫 번째 계획과 비교)
